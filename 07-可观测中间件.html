可观测中间件

它挂在每一个节点上——这是六个中间件里唯一一个"全节点"的。因为它要回答的不是"怎么改行为"，而是"刚才到底发生了什么"。没有它，其他五个中间件出了问题时你无从判断。

一次运行的时间去哪了

还是第 04 章那个案例：5 轮模型调用、4 轮工具往返。下面这张瀑布，是那次运行的完整 span 记录。点任意一行看它在记什么。

SPAN0 ────────────────────────────────── 12.6s耗时
这张图最重要的一个结论：12.6 秒里有 11.2 秒在等模型，只有 1.4 秒在跑工具。所以"优化 agent 速度"最有效的手段几乎从来不是换更快的工具或加缓存，而是减少轮次——每少一轮 model_call，就省掉 2 秒左右，顺便省掉一整段重放的 token。

span 的嵌套结构

可观测中间件不是"到处打日志"。它记的是一棵有父子关系的树，这样才能从"总耗时 12.6 秒"一路下钻到"第 4 轮那个 read_file 为什么花了 170 毫秒"。

agent.run                         12,560ms   ← 根 span，before_agent 开、after_agent 关
├─ llm.turn1                       1,980ms   model=claude-sonnet  in=1,180 out=142
├─ tool.list_dir                     230ms   /repo  exit=0  bytes=48
├─ llm.turn2                       2,200ms   in=1,486 out=168
├─ tool.read_file                    170ms   requirements.txt  bytes=132
├─ tool.search_cve                   480ms   q=django  results=1
├─ llm.turn3                       2,200ms   in=1,690 out=205
├─ llm.turn4                       1,400ms   in=2,140 out=96
├─ tool.fanout                       500ms   ← 父 span，三个并行子 span
│  ├─ tool.read_file(app.py)         210ms
│  ├─ tool.read_file(README.md)       90ms
│  └─ tool.search_cve(requests)      500ms   ← 取最长的那条
└─ llm.turn5                       2,600ms   in=2,448 out=312   finish=stop

注意 tool.fanout 这一层。并行调用在瀑布上不是一条横条，是一组并排的条，父 span 的宽度取最长的那条。如果只记总耗时，你会以为这三个工具是串行跑的，性能账全算错。

token 账本

同一个案例，把每次调用的进出 token 摊开：

轮次输入 token输出 token这一轮干了什么备注
turn 11,180142决定先看目录—
turn 21,486168读依赖 + 查 CVE新增 2 条工具消息
turn 31,690205确认漏洞影响范围—
turn 42,14096并行读三个文件一次发 3 个 tool_call
turn 52,448312产出补丁建议finish=stop
合计8,9447249,668 token—

然后是真正值得看的那一行：最终整段对话只有 2,448 token，但账单上是 8,944。同一条历史被重复计费了 3.7 倍——这就是第 04 章"每轮全量重放"的直接财务后果。

所以可观测的价值不只是"出事好查"。它是唯一能把"这个 agent 为什么贵"算清楚的工具。没有账本，你只能感觉到贵；有了账本，你知道贵在第 4 轮那次并行读文件（2,140 输入只换回 96 输出，性价比最差的一轮）。

记什么，不记什么

字段为什么记怎么记才安全
完整 prompt复现"它当时到底看到了什么"的唯一办法脱敏后存；或只存 hash + 变更 diff
tool 参数判断危险调用、排查参数错误路径、密钥、token 一律打码
tool 输出大小发现"上下文被撑爆"的源头记字节数即可，不必存全文
TTFT首 token 延迟直接决定体感速度和总耗时分开记，两者不是一回事
finish_reason区分"正常结束"和"被截断"截断要单独告警，它会悄悄丢答案
可观测本身是个隐私面：完整 prompt 里可能含用户上传的文档、数据库字段、内部路径。trace 系统往往是整个 agent 里最容易造成数据外泄的一环——它把所有东西都抄了一份，还存很久。上线前先想清楚：存多久、谁能读、哪些字段必须脱敏。
